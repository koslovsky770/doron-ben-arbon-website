# פאנל ניהול לאתר דורון בן ארבון — מפרט עיצוב

תאריך: 2026-09-06
סטטוס: מאושר לשלב התכנון המפורט (writing-plans)

## רקע ומטרה

האתר החי כיום הוא סטטי לחלוטין (`site/preview/*.html`), מתארח ב-GitHub Pages
(`github.com/koslovsky770/doron-ben-arbon-website`), בלי שרת ובלי בסיס נתונים.
כל טקסט, המלצה ופרויקט כתובים כקוד קשיח (hard-coded) בתוך כל קובץ HTML בנפרד —
כולל כפילויות (לדוגמה: commercial.html משכפל 3 פרויקטים שכבר קיימים ב-index.html).

יש גם גרסת React (`site/lovable/`) המיועדת לדחיפה עתידית ל-Lovable, אך טרם
הועלתה. וקיים פרויקט Supabase בשם `doron-ben-arbon` תחת חשבון המשתמש, שנוצר
בעבר אך עדיין לא חובר לשום דבר.

המטרה: לבנות פאנל ניהול (`/admin`) המאפשר לאודליה/דורון לערוך את תוכן האתר
בלי לגעת בקוד — טקסטים (עם עורך עשיר), המלצות (CRUD מלא) ופרויקטים (CRUD מלא,
כולל העלאת תמונה בגרירה) — כשכל הנתונים "נשמרים במסד נתונים".

**החלטה מפורשת של המשתמשת:** לא לחבר את הפרויקט ל-Supabase (או לכל בסיס נתונים
חיצוני אחר) בשלב הזה. היא עדיין שוקלת בין Lovable/Supabase לבין MySQL בשרת
פרטי, ותחליט בעתיד. לכן הארכיטקטורה כאן חייבת לבודד את שכבת האחסון כך
שההחלטה העתידית לא תדרוש בנייה מחדש של הממשק.

## ארכיטקטורה

הפרדה בין **קריאה** ל**כתיבה**:

- **קריאה (מה שהגולשים רואים):** כל 4 עמודי האתר (`index.html`, `about.html`,
  `commercial.html`, `testimonials.html`) שולפים את התוכן שלהם בזמן ריצה
  (client-side `fetch`) מקבצי JSON סטטיים תחת `site/data/`. קובץ JSON סטטי
  נטען מ-GitHub Pages בדיוק כמו כל קובץ סטטי אחר — אין צורך בשרת כדי *לקרוא*.
- **כתיבה (פאנל הניהול):** GitHub Pages לא יכול לקבל בקשות שמירה, אז הכתיבה
  קורית מול השרת המקומי הקיים (`.claude/serve.mjs`, היום שרת קבצים סטטי
  בלבד) — אליו יתווספו כמה נתיבי API. המשמעות: **הפאנל פעיל במלואו רק כשמריצים
  אותו מקומית** (`node .claude/serve.mjs` → `http://localhost:5273/admin`),
  לא מול כתובת ה-GitHub Pages החיה. זו מגבלה מודעת של השלב הזה — כשיוחלט על
  Supabase/MySQL, הכתיבה תעבור לשרת אמיתי והפאנל יעבוד מכל מקום.
- **שכבת בידוד:** כל הגישה לנתונים (גם קריאה וגם כתיבה) עוברת דרך קובץ עזר
  יחיד — `site/assets/data-store.js`. גם העמודים הציבוריים וגם פאנל הניהול
  קוראים לפונקציות שלו (`getContent`, `getTestimonials`, `saveProject` וכו'),
  ולא נוגעים ב-`fetch`/JSON ישירות. **שינוי עתידי של מקום האחסון (Supabase או
  MySQL עצמאי) הוא שינוי פנימי של הקובץ הזה בלבד** — לא של הממשק, לא של
  העמודים הציבוריים, לא של צורת הנתונים.

זרימת עדכון: עריכה בפאנל → שמירה מיידית לקובצי ה-JSON/לתמונות במחשב המקומי →
בדיקה בתצוגה המקומית → כשמרוצים, פעולת git commit + push (כמו היום) מפרסמת את
השינוי בפועל ל-GitHub Pages. אין דיפלוי אוטומטי בשלב הזה.

## מודל הנתונים

תחת `site/data/`:

- **`content.json`** — מפה שטוחה של מפתח → HTML (טקסט עשיר מסונן). מפתחות
  בקונבנציה `<עמוד>.<סקשן>.<שדה>`, למשל: `home.hero.titleStart`,
  `home.hero.paragraph`, `home.footer.blurb`, `about.hero.paragraph`,
  `commercial.hero.paragraph`, `testimonialsPage.title`. עמודי הבית מכילים
  גם כותרות שירותים (`home.services.commercial.title/description` וכו').
  רשימת המפתחות המדויקת תחולץ בזמן המימוש 1:1 מהטקסט הקיים היום בכל עמוד
  (על בסיס התבנית שכבר קיימת ב-`edit.html` עבור דף הבית).
- **`testimonials.json`** — מערך אובייקטים: `{ id, name, role, quote (HTML),
  featured (bool — מוצג בדף הבית), order }`. עמוד ההמלצות המלא מציג הכל;
  דף הבית ודף האודות מציגים רק את המסומנים `featured`, לפי `order`.
- **`projects.json`** — מערך אובייקטים: `{ id, title, description (HTML),
  location, tags: string[], category: "commercial"|"project-marketing"|
  "plots", image (נתיב יחסי, למשל "images/proj-x.jpg"), order }`. דף הבית
  מציג הכל עם טאבים לפי `category`; commercial.html מציג רק
  `category="commercial"` — אין יותר כפילות נתונים בין הקבצים.

תמונות שהועלו נשמרות בפועל תחת `site/lovable/public/images/` (אותה תיקייה
שכבר משמשת את שני הפרויקטים), עם שם קובץ שנוצר אוטומטית; ב-JSON נשמר רק
הנתיב היחסי.

## רכיבים לבנייה

1. **`site/data/*.json`** — התוכן הקיים היום, מחולץ 1:1 (בלי שינוי ויזואלי).
2. **`site/assets/data-store.js`** — שכבת הגישה היחידה לנתונים (ר' לעיל).
3. **`site/assets/rich-editor.js`** — רכיב עזר משותף: תיבת `contenteditable`
   + סרגל כלים קטן (Bold / Italic / Underline / גופן / גודל), עם ניקוי
   (sanitize) לתוצאה — allow-list של תגיות בלבד (`b,strong,i,em,u,span` עם
   `style` מוגבל ל-`font-family/font-weight/font-size/color`), בלי
   `script`/מאפייני `on*`. משמש גם בטאב "טקסטים" וגם בשדות טקסט עשיר בטאבים
   האחרים (תיאור המלצה, תיאור פרויקט).
4. **`site/admin/index.html`** (בכתובת `.../site/admin/`, באותה קונבנציה של
   `site/preview/`):
   - מסך כניסה: שדה סיסמה יחיד מול הקבוע `12345`. הצלחה → דגל ב-`localStorage`
     (`doron-admin-auth`) כדי להישאר מחוברים במכשיר, עם כפתור "התנתקות".
   - שלושה טאבים:
     - **טקסטים** — מקובץ לפי עמוד, כל שדה עם תווית ברורה (בעברית) ותיבת
       העריכה העשירה; שמירה אוטומטית ב-blur עם הודעת "נשמר ✓".
     - **המלצות** — רשימת כרטיסים, הוספה/עריכה/מחיקה, תיבת סימון "הצג בדף
       הבית", כפתורי הזזה למעלה/למטה לסדר.
     - **פרויקטים** — טאבים לפי קטגוריה, הוספה/עריכה/מחיקה, אזור גרירת
       תמונה (drag-and-drop, לא שדה לינק) עם תצוגה מקדימה לפני שמירה.
5. **הרחבת `.claude/serve.mjs`** — נתיבי API: `GET/POST /api/content`,
   `GET/POST/DELETE /api/testimonials[/:id]`, `GET/POST/DELETE
   /api/projects[/:id]`, `POST /api/upload-image`. כל בקשת כתיבה בודקת כותרת
   סיסמה מול `12345` בצד השרת (הגנה בסיסית גם אם עוקפים את מסך הכניסה
   בדפדפן). כתיבה לקובצי JSON היא אטומית (כתיבה לקובץ זמני + החלפה) כדי
   שקריסה באמצע לא תשחית נתונים.
6. **עדכון 4 עמודי `site/preview/*.html`** — הסרת המערכים הקשיחים (PROJECTS,
   TESTIS, GREVIEWS, SERVICES, LISTINGS וכו') והחלפתם בקריאה ל-`data-store.js`
   בזמן טעינת הדף; תיוג כל שדה טקסט ב-`data-field="<מפתח>"` (המשך של
   קונבנציית ה-`data-edit` שכבר קיימת כטיוטה ב-`edit.html`).

## טיפול בשגיאות

- העלאת תמונה: בדיקת סוג קובץ (jpg/png/webp) וגודל מקסימלי (~5MB); דחייה עם
  הודעה ברורה בפאנל אם לא עומד בתנאים.
- אם קובץ JSON חסר/פגום, העמוד הציבורי נופל חזרה לתוכן ברירת המחדל (snapshot
  שנשמר בהיסטוריית git) במקום להישבר.
- בקשת כתיבה בלי סיסמה תקינה → 401 מהשרת, והפאנל מציג הודעת שגיאה.

## בדיקות

אין מסגרת בדיקות אוטומטיות בפרויקט הזה (כמו היום — הכל נבדק ויזואלית
בדפדפן). האימות יהיה ידני/ויזואלי: הרצת השרת המקומי, מעבר על כל טאב בפאנל,
ואימות שהעמודים הציבוריים (כשה-JS-store פעיל) משקפים את השינויים אחרי רענון.
בנוסף, בדיקה שקריאה בלבד (כמו שיקרה בפועל ב-GitHub Pages) עדיין מציגה את
האתר נכון גם כששרת ה-API לא רץ.

## מחוץ לתחום (לשלב הזה)

- חיבור בפועל ל-Supabase (הפרויקט `doron-ben-arbon` שכבר קיים) או להקמת שרת
  MySQL — יוחלט וייבנה בנפרד כשהמשתמשת תחליט.
- ביקורות גוגל חיות (Places API) — כבר מתועד כצעד עתידי נפרד ב-`site/README.md`,
  לא חלק מהפאנל הזה.
- גרסת ה-React/Lovable (`site/lovable/`) — הפאנל הזה מיועד לאתר הסטטי בלבד.

## הערה על גמישות עתידית

מבנה הנתונים (מפות מפתח-ערך + מערכי אובייקטים עם שדות פשוטים, ותמונה כנתיב
יחסי לקובץ בדיסק) הוא גנרי במכוון — מתאים 1:1 גם לטבלת MySQL עצמאית וגם
לטבלת Supabase/Postgres, בלי שינוי מבנה. כשתתקבל החלטה, העבודה תהיה החלפת
התוכן הפנימי של `data-store.js` (וב-Node server, סוג ה-storage) — לא בנייה
מחדש של הפאנל או העמודים הציבוריים.
