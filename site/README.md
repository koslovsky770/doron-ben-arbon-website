# דורון בן ארבון — דף הבית (שלב 1)

דף בית + תפריט, לפי מסמך האיפיון, בעיצוב תבנית ה־Figma
*Free Real Estate Portfolio website template* — RTL מלא, מוכן לדחיפה ל־Lovable.

## מבנה

```
site/
├─ preview/index.html        ← תצוגה מקדימה עצמאית (לפתיחה בדפדפן)
└─ lovable/                  ← מה שנדחף ל-Lovable
   ├─ tailwind.config.ts
   ├─ public/
   │  ├─ images/*.jpg        ← 12 תמונות שנוצרו
   │  └─ fonts/Polin-*.woff2 ← פונט המותג
   └─ src/
      ├─ index.css           ← @font-face + טוקני עיצוב (HSL CSS variables)
      ├─ data/site.ts        ← כל התוכן במקום אחד
      ├─ pages/Index.tsx
      └─ components/site/    ← Navbar, Hero, About, FeaturedProjects, Services,
                                GoogleReviews, Testimonials, CtaBanner, Footer,
                                Logo, Icons
```

שני הקבצים זהים ויזואלית. ה־HTML הוא לתצוגה בלבד ואינו נדחף.

## טיפוגרפיה

**Polin** — פונט המותג, בשני חתכים בלבד (Regular + Bold). ב־`index.css` מוגדרים
טווחי משקל כדי שכל `font-weight` של Tailwind ימופה לקובץ אמיתי:

| טווח | קובץ |
|---|---|
| `100–500` (normal / medium) | `Polin-Regular.woff2` |
| `600–900` (semibold → black) | `Polin-Bold.woff2` |

בלי זה הדפדפן היה מייצר bold מזויף. `Assistant` נשאר בסטאק רק כגיבוי לתו חסר.

סקאלה: `text-d1` = 92px, `text-d2` = 59px, `text-d3` = 24px — עם `clamp()`.

### ביקורות חיות (שלב הבא)

הקרוסלה קוראת מהמערך `googleReviews`. אי אפשר למשוך ביקורות מגוגל ישירות
מהדפדפן — אין endpoint ציבורי, CORS חוסם, וגרידה נוגדת את תנאי השימוש.
הדרך הנתמכת היא **Google Places API** דרך שרת:

1. ב־Lovable: להפעיל Supabase ולהוסיף edge function `google-reviews`.
2. לשמור `GOOGLE_MAPS_API_KEY` כסוד (לא בקוד הלקוח).
3. ה־function קוראת ל־Place Details ומחזירה את `result.reviews`.
4. להחליף ב־`GoogleReviews.tsx` את הקריאה למערך הסטטי ב־`useQuery` לפונקציה,
   עם המערך הנוכחי כ־fallback.

מגבלה של גוגל: Place Details מחזיר **עד 5 ביקורות**, לא את כל ה־23.
כדי להציג את כולן צריך שירות צד־שלישי (Elfsight / Trustindex / EmbedSocial).

את ה־`place_id` בפורמט `ChIJ…` צריך לשלוף פעם אחת דרך Find Place; מה שידוע
כרגע שמור ב־`googleBusiness`: `cid` ו־`fid`.

## סקשן "איך זה עובד" (שלושת עמודי השירותים)

`ProcessSlider` — סליידר עריכתי אופקי RTL, בין ה-Hero לגלריית הפרויקטים בכל
אחד משלושת עמודי השירותים (תיווך מסחרי, שיווק פרויקטים, מגרשים). 5 שלבים
ממוספרים (01–05), כרטיס פעיל גדול + הצצה לכרטיס הבא, קו התקדמות דק במקום
נקודות, וגרירה בעכבר בדסקטופ (גלילת מגע טבעית במובייל — לא נגעתי בה).

- **תוכן** — `commercialPage.process` / `projectMarketingPage.process` /
  `plotsPage.process` ב-`site.ts`. תוכן תיווך מסחרי נמסר כלשונו; שיווק
  פרויקטים ומגרשים הם התאמה קלה של אותם 5 שלבים לכיוון הרלוונטי (למשל
  "מסננים את הנכסים" → "ממפים את השוק" בשיווק פרויקטים).
- **מנגנון** — `overflow-x-auto` + `scroll-snap-type: x proximity` (לא
  `mandatory` — זה התנגש עם `scrollBy({behavior:"smooth"})` של כפתורי
  החצים וביטל את האנימציה כמעט מיד), עם דעיכת opacity/scale לפי מרחק כל
  כרטיס ממרכז המסלול (`measureProcess`/`measure` ב-React).
- **גרירה** — Pointer Events, מסונן ל-`pointerType==="mouse"` בלבד כדי
  שמגע במובייל יישאר גלילה טבעית של הדפדפן ולא יתנגש עם הקוד.
- **React** — קומפוננטה משותפת אחת, `components/site/ProcessSlider.tsx`,
  מקבלת `{title, steps, closing}` ומוזרקת בכל אחד משלושת דפי השירות.

שלושה בלוקים של **תוכן דמה** (`plotsPage.listings.placeholder` ב-`site.ts`),
עם תמונת placeholder מקווקוות ("תמונה תתווסף בהמשך") במקום תמונה אמיתית.
גם ההירו מסומן בטקסט כ"לדוגמה — יעודכן מול דורון". יש להחליף את כל זה
בתוכן אמיתי ברגע שיתקבל. תצוגה מקדימה: `site/preview/plots.html`.

## עמוד צור קשר

לפי מסמך האיפיון ("טלפון, וואטסאפ, מייל, כתובת המשרד") **ובנוסף** טופס
השארת פרטים, לפי בקשה מפורשת שדורסת את הכלל הקודם "בלי טופס יצירת קשר"
(ראו "מה שונה מהתבנית המקורית" למעלה — זה עדיין נכון לשאר האתר, רק לא
לעמוד הזה).

```
src/pages/Contact.tsx
└─ Navbar (current="/contact") → כותרת קצרה → ContactForm → Footer
```

- **השדות** — שם מלא, טלפון, אימייל (לא חובה), תחום עניין (סלקט: תיווך
  מסחרי / שיווק פרויקטים / מגרשים / אחר), הודעה. בלי checkbox של "תנאי
  שימוש" — אין באתר עמודי תנאים/פרטיות אמיתיים, אז לא הוספנו קישור לדבר
  שלא קיים (אותו עיקרון שהוביל להשמטת "הצוות" ו"פרסים" בעמוד האודות).
- **אין backend** — Supabase לא מופעל בפרויקט הזה, אז "שליחה" לא שומרת
  כלום בשרת. במקום זה, לחיצה על הכפתור בונה הודעת וואטסאפ עם כל פרטי
  הטופס ופותחת אותה לדורון — אותו ערוץ שכל שאר כפתורי הוואטסאפ באתר
  משתמשים בו. אם ירצו שמירה אמיתית של פניות (מייל / דאטהבייס), צריך
  להפעיל Supabase ב-Lovable ולחבר edge function.
- **בתפריט** — נוסף קישור "צור קשר" ל-`navLinks` (אחרי "המלצות") ול-Footer,
  בכל עמוד באתר. תצוגה מקדימה: `site/preview/contact.html`.
