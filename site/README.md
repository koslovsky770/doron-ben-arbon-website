# דורון בן ארבון — דף הבית (שלב 1)

דף בית + תפריט, לפי מסמך האיפיון, בעיצוב תבנית ה־Figma
*Free Real Estate Portfolio website template* — RTL מלא, מוכן לדחיפה ל־Lovable.

## מבנה

```
site/
├─ preview/index.html        ← תצוגה מקדימה עצמאית (לפתיחה בדפדפן)
└─ lovable/                  ← מה שנדחף ל-Lovable
   ├─ tailwind.config.ts
   ├─ public/
   │  ├─ images/*.jpg        ← 12 תמונות שנוצרו
   │  └─ fonts/Polin-*.woff2 ← פונט המותג
   └─ src/
      ├─ index.css           ← @font-face + טוקני עיצוב (HSL CSS variables)
      ├─ data/site.ts        ← כל התוכן במקום אחד
      ├─ pages/Index.tsx
      └─ components/site/    ← Navbar, Hero, About, FeaturedProjects, Services,
                                GoogleReviews, Testimonials, CtaBanner, Footer,
                                Logo, Icons
```

שני הקבצים זהים ויזואלית. ה־HTML הוא לתצוגה בלבד ואינו נדחף.

## טיפוגרפיה

**Polin** — פונט המותג, בשני חתכים בלבד (Regular + Bold). ב־`index.css` מוגדרים
טווחי משקל כדי שכל `font-weight` של Tailwind ימופה לקובץ אמיתי:

| טווח | קובץ |
|---|---|
| `100–500` (normal / medium) | `Polin-Regular.woff2` |
| `600–900` (semibold → black) | `Polin-Bold.woff2` |

בלי זה הדפדפן היה מייצר bold מזויף. `Assistant` נשאר בסטאק רק כגיבוי לתו חסר.

סקאלה: `text-d1` = 92px, `text-d2` = 59px, `text-d3` = 24px — עם `clamp()`.

### ביקורות חיות (שלב הבא)

הקרוסלה קוראת מהמערך `googleReviews`. אי אפשר למשוך ביקורות מגוגל ישירות
מהדפדפן — אין endpoint ציבורי, CORS חוסם, וגרידה נוגדת את תנאי השימוש.
הדרך הנתמכת היא **Google Places API** דרך שרת:

1. ב־Lovable: להפעיל Supabase ולהוסיף edge function `google-reviews`.
2. לשמור `GOOGLE_MAPS_API_KEY` כסוד (לא בקוד הלקוח).
3. ה־function קוראת ל־Place Details ומחזירה את `result.reviews`.
4. להחליף ב־`GoogleReviews.tsx` את הקריאה למערך הסטטי ב־`useQuery` לפונקציה,
   עם המערך הנוכחי כ־fallback.

מגבלה של גוגל: Place Details מחזיר **עד 5 ביקורות**, לא את כל ה־23.
כדי להציג את כולן צריך שירות צד־שלישי (Elfsight / Trustindex / EmbedSocial).

את ה־`place_id` בפורמט `ChIJ…` צריך לשלוף פעם אחת דרך Find Place; מה שידוע
כרגע שמור ב־`googleBusiness`: `cid` ו־`fid`.

## סקשן "איך זה עובד" (שלושת עמודי השירותים)

`ProcessSlider` — סליידר עריכתי אופקי RTL, בין ה-Hero לגלריית הפרויקטים בכל
אחד משלושת עמודי השירותים (תיווך מסחרי, שיווק פרויקטים, מגרשים). 5 שלבים
ממוספרים (01–05), כרטיס פעיל גדול + הצצה לכרטיס הבא, קו התקדמות דק במקום
נקודות, וגרירה בעכבר בדסקטופ (גלילת מגע טבעית במובייל — לא נגעתי בה).

- **תוכן** — `commercialPage.process` / `projectMarketingPage.process` /
  `plotsPage.process` ב-`site.ts`. תוכן תיווך מסחרי נמסר כלשונו; שיווק
  פרויקטים ומגרשים הם התאמה קלה של אותם 5 שלבים לכיוון הרלוונטי (למשל
  "מסננים את הנכסים" → "ממפים את השוק" בשיווק פרויקטים).
- **מנגנון** — `overflow-x-auto` + `scroll-snap-type: x proximity` (לא
  `mandatory` — זה התנגש עם `scrollBy({behavior:"smooth"})` של כפתורי
  החצים וביטל את האנימציה כמעט מיד), עם דעיכת opacity/scale לפי מרחק כל
  כרטיס ממרכז המסלול (`measureProcess`/`measure` ב-React).
- **גרירה** — Pointer Events, מסונן ל-`pointerType==="mouse"` בלבד כדי
  שמגע במובייל יישאר גלילה טבעית של הדפדפן ולא יתנגש עם הקוד.
- **React** — קומפוננטה משותפת אחת, `components/site/ProcessSlider.tsx`,
  מקבלת `{title, steps, closing}` ומוזרקת בכל אחד משלושת דפי השירות.

שלושה בלוקים של **תוכן דמה** (`plotsPage.listings.placeholder` ב-`site.ts`),
עם תמונת placeholder מקווקוות ("תמונה תתווסף בהמשך") במקום תמונה אמיתית.
גם ההירו מסומן בטקסט כ"לדוגמה — יעודכן מול דורון". יש להחליף את כל זה
בתוכן אמיתי ברגע שיתקבל. תצוגה מקדימה: `site/preview/plots.html`.

## עמוד צור קשר

לפי מסמך האיפיון ("טלפון, וואטסאפ, מייל, כתובת המשרד") **ובנוסף** טופס
השארת פרטים, לפי בקשה מפורשת שדורסת את הכלל הקודם "בלי טופס יצירת קשר"
(ראו "מה שונה מהתבנית המקורית" למעלה — זה עדיין נכון לשאר האתר, רק לא
לעמוד הזה).

```
src/pages/Contact.tsx
└─ Navbar (current="/contact") → כותרת קצרה → ContactForm → Footer
```

- **השדות** — שם מלא, טלפון, אימייל (לא חובה), תחום עניין (סלקט: תיווך
  מסחרי / שיווק פרויקטים / מגרשים / אחר), הודעה. בלי checkbox של "תנאי
  שימוש" — אין באתר עמודי תנאים/פרטיות אמיתיים, אז לא הוספנו קישור לדבר
  שלא קיים (אותו עיקרון שהוביל להשמטת "הצוות" ו"פרסים" בעמוד האודות).
- **בתפריט** — נוסף קישור "צור קשר" ל-`navLinks` (אחרי "המלצות") ול-Footer,
  בכל עמוד באתר. תצוגה מקדימה: `site/preview/contact.html`.

### שליחת הטופס — Resend + נפילה חזרה לוואטסאפ

הוחלט (לא Supabase) להשתמש בשרת cPanel שדורון/הסוכנות יתקינו את האתר
עליו, עם PHP רגיל. הטופס שולח בקשת POST ל-`api/send-contact.php`
(מקביל: `ContactForm.tsx` שולח ל-`/api/send-contact.php`), שקוראת ל-API
של [Resend](https://resend.com) ושולחת מייל עם כל פרטי הפנייה.

- **קבצים** — `site/preview/api/send-contact.php` (לתצוגה המקדימה) ו-
  `site/lovable/public/api/send-contact.php` (עותק זהה עבור ה-build של
  Lovable/Vite). שני הקבצים משתמשים באותו קוד PHP פשוט (תואם ~7.1+, בלי
  תחביר PHP 8 ייחודי) שקורא ל-Resend עם `curl`.
- **קונפיגורציה** — משתני סביבה `RESEND_API_KEY`, `RESEND_FROM`,
  `RESEND_TO` (יש `.env.example` ליד כל קובץ PHP). ב-cPanel: להגדיר
  כמשתני סביבה אמיתיים אם אפשר, או להעתיק את `.env.example` ל-`.env`
  באותה תיקייה ולמלא ערכים אמיתיים — **הקובץ `.env` ב-gitignore ולעולם
  לא נדחף ל-git**.
- **דומיין שליחה** — בחשבון ה-Resend המחובר יש כרגע רק דומיין מאומת של
  לקוח אחר (`mrestates.co.il`). כדי לשלוח מיילים אמינים בשם דורון צריך
  לאמת דומיין משלו (למשל `ba-yazamut.co.il`) ב-Resend — זה דורש הוספת
  רשומות DNS, ואפשר לעשות את זה בכל שלב שיש שליטה על ה-DNS של הדומיין
  (למשל דרך Cloudflare), בלי קשר לתזמון העלאת האתר ל-cPanel עצמו.
- **נפילה חזרה (fallback)** — אם הבקשה ל-`api/send-contact.php` נכשלת
  (סטטוס לא תקין, או שהתגובה לא JSON עם `{ok:true}` — בדיוק מה שקורה
  היום ב-GitHub Pages, שמחזיר את קובץ ה-PHP הגולמי בתור טקסט סטטי עם
  200 OK), הטופס נופל אוטומטית חזרה לפתיחת וואטסאפ עם כל הפרטים, בדיוק
  כמו שהיה קודם. כך האתר החי ממשיך לעבוד כרגיל (וואטסאפ) גם לפני
  שההעברה ל-cPanel + הגדרת Resend הושלמה, ועובר אוטומטית למייל ברגע
  שהשרת שם באוויר עם המפתח מוגדר.
- **כתובת יעד** — `bayazamut@gmail.com` (לא `doron@ba-yazamut.co.il`,
  שמסומן בקוד כלא מאומת מול דורון).

## עריכה ויזואלית באתר החי

בכל עמוד אמיתי (חוץ מ־`privacy.html`, `accessibility.html` ו־`testimonials.html`
— ראו "פרטיות ונגישות" למטה) מוטמע מנוע עריכה קטן, בלי ספריות חיצוניות:

- כל טקסט עם `data-edit="site.ts.some.path"` ניתן ללחיצה לעריכה; `data-edit-block`
  על מכל מסמן את "הבלוק" שנמחק כולו בכפתור המחיקה.
- שינויים נשמרים ב־`localStorage` (מפתח `doron-site-edits-v1`, משותף לכל
  העמודים באותו דומיין) ומוצגים מחדש בכל טעינת עמוד.
- כפתור צף "📋 העתיקי שינויים לקלוד" בונה סיכום לפני/אחרי של כל השינויים
  בעמוד הנוכחי בלבד (מסונן לפי מה שבאמת קיים בעמוד — ולא כולל שיוריים
  מעמודים אחרים שחולקים את אותו מפתח localStorage) ומעתיק ללוח.
- `index.html` בלבד: הכרטיסים בסקשן "פרויקטים נבחרים" נבנים מחדש בכל
  החלפת טאב סינון, ולכן העמוד חושף `window.__veApplyEdits` כדי שהעריכות
  יוחלו מחדש אחרי כל רינדור.

## סליידר "איך זה עובד" — תיקון שקיפות טקסט

הטקסט בכרטיסים הפעילים נראה אפור/שקוף בבדיקה חזותית. הסיבה: דעיכת ה־`opacity`
לפי מרחק מהמרכז (לצד ה־`scale`) גרמה לכרטיס הפעיל עצמו להיראות דהוי כשלא
היה בדיוק במרכז. הוסר לגמרי דעיכת ה־opacity ונשארה רק דעיכת `scale` (הקטנה
עדינה יותר, עד 5% במקום 8%), גם ב־`ProcessSlider.tsx` וגם בשלושת קבצי
ה־preview (commercial/project-marketing/plots).

## פרטיות ונגישות

נוספו שני עמודים חדשים, `Privacy.tsx`/`privacy.html` ו־`Accessibility.tsx`/
`accessibility.html`, לפי מבנה בסיסי של חוק הגנת הפרטיות (התשמ״א-1981) וחוק
שוויון זכויות לאנשים עם מוגבלות + תקנות נגישות (WCAG 2.0 AA / ת״י 5568):

- תוכן ב־`privacyPage`/`accessibilityPage` ב־`site.ts` (כותרת, תאריך עדכון,
  מבוא, וסקשנים של כותרת+גוף). **זו נקודת פתיחה בלבד — לא ייעוץ משפטי.**
  מומלץ שעורך דין יעבור על הנוסח, ושדורון יאשר את פרטי הנגישות הפיזית
  של המשרד (מסומן ב־TODO בקוד).
- בכוונה **בלי** תיוג `data-edit` על שני העמודים האלה — כדי לא לחשוף טקסט
  משפטי רגיש לעריכה מקרית דרך מנגנון העריכה הוויזואלי.
- **פופאפ הסכמה** (`ConsentBanner.tsx` / באנר זהה בכל קובצי ה-preview) —
  מופיע פעם אחת בתחתית המסך בכל עמוד עד לחיצה על "אישור", לפי `localStorage`
  (מפתח `doron-privacy-consent`), עם קישור למדיניות הפרטיות.

## תיקונים נוספים

- **כפתור טופס יצירת קשר** — "שליחה בוואטסאפ" → "חזרו אלי ←" (`contactPage.form.submitLabel`).

  הוחלף ב"שלום, דורון, אני פונה אליך דרך האתר. אשמח שתחזור אלי." — בכל
  העמודים, חוץ מהודעת הליד המובנית של טופס יצירת הקשר עצמו שנשארת כפי שהייתה.
- **`testimonials.html`** — ניווט תפריט/פוטר שהצביע עדיין לעוגן הישן
  `index.html#services` תוקן לקישורים האמיתיים (commercial/project-marketing/
  plots), ונוסף קישור חסר ל"צור קשר" בתפריט ובפוטר.
- **תוכן עמוד אודות** — עודכנו `about.paragraph`, שלושת ה־`aboutPage.story.values`,
  ה־bio ב־`aboutPage.story` וה־`aboutPage.achievements.paragraph`, לפי עריכה
  אמיתית שדורון ביצע דרך מנגנון העריכה הוויזואלי. טקסט מודגש (`**כך**`) בעריכה
  הוויזואלית מתורגם ל־`<b>` ב-HTML, ולערך React דרך helper חדש —
  `renderBold()` ב־`components/site/RichText.tsx` — כי JSX רגיל לא מרנדר
  תגי HTML מתוך מחרוזת; אומץ כמוסכמה קבועה לכל טקסט שעשוי להגיע עם `**bold**`
  מהעורך הוויזואלי.
